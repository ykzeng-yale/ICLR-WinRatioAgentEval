# Agent evaluation design and reusable harness audit

Checked **2026-09-21 UTC**. This is a bounded primary-source and static-code audit, not a systematic literature review, benchmark reproduction, or validation of this paper's agents. No model calls, package installation, weight downloads, benchmark execution, Git mutation, or owner-source edits were performed. Recommendations below are proposed work, not completed experiments.

**Recommendation:** preserve the current CPU validation gates, and add at most one empirical extension using existing outputs: stronger-test sensitivity for the HumanEval portion of the coding study. Reuse EvalPlus's verifier and selected Inspect logging concepts; a wholesale harness migration or additional benchmark collection is not justified by this audit.

## 1. Current project constraints read

- [Coding collection scope](open_coding_collection/README.md), lines 5–13: 1,182 retained records, 591 tasks, 295 preassigned first-pass cross-task pairs; same-task comparisons are descriptive. The published projection omits programs and verifier stderr. Labels are archived, not independently regenerated. All sanitized MBPP tasks were used, not just a held-out test split; model requests with seeds do not establish bit-identical or independent replication. Retrospective crossings did not stop execution.
- [Airline collection scope](open_airline_collection/README.md), lines 7–25: 196 planned units, 194 trajectories and two failure placeholders; 206 attempted executions include 12 discarded attempts. Failed-attempt cost is incomplete. Collection ran all A then all B; two trial seeds were reused across tasks and arms. The accepted replay conditions on the completed array, and does not estimate a fresh deployment effect. Source seed forwarding is not proof of sampler receipt.
- [CPU v1 disposition](../reviews/cpu_v1_delivery_root_disposition.md), lines 13–20, 28–44, 48–56: saved-flag reproduction is not latent-path reproduction; v1 used a different interval adapter and omitted some completion-index-changing looks. Proposed v2 needs an explicit legal event schedule, common comparison opportunities, verified roster-derived horizon, executable pin and reviewed adapter. A paired replay after development is not fresh independent calibration. Null/abstention outcomes remain scientifically acceptable.
- [Existing decision/grader ablations](decision_ablation_protocol.md), lines 5–49: synthetic component-only, weighted-utility, Pareto and differential-grader studies already exist. Their objectives differ, and simulated error envelopes are assumptions. Repeating these studies is lower priority than checking actual archived coding labels.

| Yao et al., **τ-bench**, [arXiv 2406.12045v1](https://arxiv.org/html/2406.12045v1), §§3–5 | Database and required-output checks define binary reward, but reward 1 need not imply full policy compliance. `pass^k` means all k repeated task trials succeed; `pass@k` means at least one does. Repetition count is a design choice, not a guarantee of independence. | Our local-model substitution evaluates a different simulator/agent system. Freeze both roles and all judge roles, rather than describing the benchmark name as a complete measurement specification. Use existing task complexity metadata descriptively, not for outcome-driven selection. |
| Liu et al., **EvalPlus**, [arXiv 2305.01210v3](https://arxiv.org/html/2305.01210v3), NeurIPS 2023; §§1–3, input contracts and test reduction | Stronger generated/mutated tests expose errors missed by original tests and can change model rankings. Tests rely on valid-input contracts and reference implementations; this is stronger checking, not proof of arbitrary program correctness. | Regrade stored outputs with fixed released tests. A public test suite is “hidden” only relative to agent exposure; it does not establish absence from model training. No new LLM test generation is needed. |
| UK AI Security Institute, **Inspect AI**, current [model](https://inspect.aisi.org.uk/models.html), [log](https://inspect.aisi.org.uk/eval-logs.html), and [scorer](https://inspect.aisi.org.uk/scorers.html) documentation; pinned implementation below | Provides model adapters, per-sample/epoch logs, usage fields and rescoring. Raw request/response logging defaults to a few calls per model plus errors; logging every call requires an explicit option. | Reuse data structures and deterministic scorers selectively. Preserve original logs, a complete attempt ledger, and publication-safe projections. Inspect is scaffolding, not a sequential inference or causal-design guarantee. |

### EvalPlus: useful verifier, with roster and runtime contracts

**Observed:** [evaluate.py, lines 144–156](https://github.com/evalplus/evalplus/blob/26d6d00bb1fd0fa37f39c99d5290da67891d1c5e/evalplus/evaluate.py#L144) invokes generation when model keyword arguments are supplied; archived-sample evaluation takes a separate path. Lines 173–178 reuse existing result files; lines 213–243 warn/skip unknown task IDs and assert full dataset coverage. The [executor, lines 230–281](https://github.com/evalplus/evalplus/blob/26d6d00bb1fd0fa37f39c99d5290da67891d1c5e/evalplus/eval/__init__.py#L230) uses reference-time-dependent limits, records pass/fail/timeout, and kills overlong subprocesses. Its [guard, lines 102–112](https://github.com/evalplus/evalplus/blob/26d6d00bb1fd0fa37f39c99d5290da67891d1c5e/evalplus/eval/utils.py#L102) explicitly is not a security sandbox. The README records MBPP+ removals and ground-truth fixes. Local generation backends exist, but generation is unnecessary here.

**Adaptation:** pin test bytes, reference solutions, evaluator, environment and timeout policy; use a separate output directory to avoid stale cached grades. Verify the complete ID mapping before scoring; do not silently interpret omitted MBPP tasks as passes or failures. A task is the comparison unit; extra test cases are verifier coverage, not independent agent runs. Execute stored programs only in a separately prepared sandbox. This audit did not execute them or assess sandbox isolation.

### Inspect: reusable adapters/logs, defaults require explicit policy

**Observed:** [Epochs, lines 5–18](https://github.com/UKGovernmentBEIS/inspect_ai/blob/ec4dfc6953784dc45b79de3147530c89868c6e26/src/inspect_ai/_eval/task/epochs.py#L5) repeats samples and defaults to mean score reduction. [GenerateConfig, lines 207–220 and 252–253](https://github.com/UKGovernmentBEIS/inspect_ai/blob/ec4dfc6953784dc45b79de3147530c89868c6e26/src/inspect_ai/model/_generate_config.py#L207) documents unlimited retries absent a limit, unset request/attempt timeouts, and provider-dependent seed support. [Error handling, lines 6–20](https://github.com/UKGovernmentBEIS/inspect_ai/blob/ec4dfc6953784dc45b79de3147530c89868c6e26/src/inspect_ai/_eval/task/error.py#L6) defaults to failing on any sample error, with configurable thresholds. [Ollama, lines 10–27](https://github.com/UKGovernmentBEIS/inspect_ai/blob/ec4dfc6953784dc45b79de3147530c89868c6e26/src/inspect_ai/model/_providers/ollama.py#L10) uses a localhost OpenAI-compatible endpoint; vLLM also has a local adapter. [ModelUsage, lines 17–43](https://github.com/UKGovernmentBEIS/inspect_ai/blob/ec4dfc6953784dc45b79de3147530c89868c6e26/src/inspect_ai/model/_model_output.py#L17) distinguishes input, cache, output and optional monetary cost fields.

**Adaptation:** preserve `(task, arm, replicate, attempt)` before epoch reduction; averaging does not create independent replication. Explicitly cap retries, calls, tokens and elapsed time. Record requested and effective provider settings, unavailable usage as missing, and aborted attempts in the planned denominator. `--model none` removes an ambient main model, but does not prohibit explicitly invoked scorer/model roles. For a no-model regrade, use a deterministic scorer and a test that rejects model/network calls. Full private request receipts and redacted public summaries serve different purposes; do not publish secrets or unrelated host details. A logging migration is optional and must not alter the frozen primary experiment.

### τ²-bench: reuse tasks/checks, preserve our denominator and role choices

**Observed:** [config.py, lines 4–43](https://github.com/sierra-research/tau2-bench/blob/b7ea9074c1cba482b30687fecdb5c8425fd6f619/src/tau2/config.py#L4) defaults to one trial, GPT-4.1 agent/user/NL-assertion roles, and retry settings. LiteLLM supplies provider routing; an open-source harness alone does not mean model-free or local execution. [batch.py, lines 741–750 and 816–832](https://github.com/sierra-research/tau2-bench/blob/b7ea9074c1cba482b30687fecdb5c8425fd6f619/src/tau2/runner/batch.py#L741) draws trial seeds, reusing each across tasks. [agent_metrics.py, lines 129–166](https://github.com/sierra-research/tau2-bench/blob/b7ea9074c1cba482b30687fecdb5c8425fd6f619/src/tau2/metrics/agent_metrics.py#L129) excludes infrastructure-error simulations. [Communication evaluation, lines 62–79](https://github.com/sierra-research/tau2-bench/blob/b7ea9074c1cba482b30687fecdb5c8425fd6f619/src/tau2/evaluator/evaluator_communicate.py#L62) checks substrings; [reward dispatch](https://github.com/sierra-research/tau2-bench/blob/b7ea9074c1cba482b30687fecdb5c8425fd6f619/src/tau2/evaluator/evaluator.py#L24) selects components via task reward basis. [Usage aggregation, lines 501–514](https://github.com/sierra-research/tau2-bench/blob/b7ea9074c1cba482b30687fecdb5c8425fd6f619/src/tau2/utils/llm_utils.py#L501) skips messages lacking usage after a warning; such a sum is not a verified complete resource total.

**Adaptation:** retain the project's 196 planned-unit denominator and missing-cost indicators. Keep success, policy findings, simulator failures and infrastructure failures distinguishable. Declare every role's model and every active reward component; replacing a judge or simulator changes the measured system. Stored dialogue checks could later audit substring false positives, but that would be a separate, explicitly defined adjudication study. Do not run an LLM-based regrader under a CPU-only label.

AgentBench additionally provides a [local FastChat configuration](https://github.com/THUDM/AgentBench/blob/d1e4a10db08c87075c78972e48ecc182be03e2d5/configs/agents/fs_agent.yaml) alongside its proprietary API example. This establishes adapter availability, not tested compatibility with our model, task roster, logger or inference rules.

## 4. Smallest informative next design — proposed, not executed

1. **Finish the existing CPU contract review first.** Follow the current root disposition: common all-required-event schedule through finalization; the same pinned feasible-completion adapter; original seed-coordinate replay identified as developed-after-v1; roster-derived horizon; component-gate and width diagnostics. Do not add a new broad grid or change margins to obtain a positive decision. These are measurement and validation repairs, not more agent samples.
2. **One bounded empirical addition: archived HumanEval verifier sensitivity.** The existing coding roster includes 164 HumanEval tasks, potentially 328 arm outputs. Before reading new grades, verify raw programs for both arms against the frozen source hashes, task IDs and prompts. The current public projection lacks those programs; availability is a real prerequisite. Freeze the entire eligible HumanEval roster by metadata, evaluator/test bytes, timeout policy, old/new grade definitions and reporting plan. Do not select tasks by earlier success or system advantage. If raw programs cannot be recovered with provenance, report that limit rather than reconstructing outputs.
3. **Primary descriptive outputs for that addition:** per-arm base/stronger-test disagreement counts; all four paired success categories; same-task success contrast; and the existing hierarchy's net-preference change when only its success label changes. Hold archived latency/tokens fixed and keep resource tiers eligible only under the specified joint-success rule. Report timeout separately. Tests, trajectories and repeated evaluations of one program are not extra task samples. Preserve old grades beside new grades. With already observed outputs this is exploratory measurement sensitivity, not a new prospective A/B trial or certification of true correctness.
4. **Compute containment:** no generation or LLM grading; at most 328 distinct stored programs, one pass through the fixed suites, an explicit low worker count and predeclared sandbox/time limits. Test cases and base/plus grading can execute each program repeatedly; log those calls rather than treating 328 as the execution count. Preserve ungraded records if a total resource cap is reached. HumanEval-first avoids quietly equating the project's all-sanitized MBPP roster with the smaller, revised MBPP+ roster. A later MBPP extension requires an explicit intersection/exclusion table and a new scope decision, not silent pooling. No calibrated false-positive/false-negative grader rates can be inferred from two imperfect test suites alone.
5. **Optional small reuse check, not another study:** map a handful of archived success, task-failure, timeout, missing-usage and retry records into an Inspect-style schema; require exact task/arm/attempt preservation and agreement with current project metrics. Keep the statistical monitor external and unchanged. Adopt a full harness only after a demonstrated integration benefit, since changing execution/logging infrastructure before freeze adds its own validation burden.

For any later authorized fresh collection, task selection/pairing, replicate seeds, serving order, role models, verifier version, attempt accounting, completion-event batching and enrollment/finalization caps belong in the frozen design. Repeated tasks are clusters for descriptive reliability summaries; the sequential target still requires its own conditional-mean/assignment argument. Distinct task or seed identifiers do not establish that argument. Report terminal nondecision and missingness as outcomes; framework adoption, positive controls and a passing mock suite cannot establish deployment validity.

## 5. Acceptance limits

This audit supports selective code reuse and the proposed stronger-verifier extension. It does not authorize collection, attest to the current live harness, validate all upstream implementations, establish independence from a framework default, or close the paper's empirical milestones. Six source groups were prioritized; only selected paper sections and four repository snapshots were inspected. The three deeper source-code reads were EvalPlus, Inspect and τ²-bench; AgentBench was limited to paper/README/configuration inspection. No third-party software was imported or executed.
