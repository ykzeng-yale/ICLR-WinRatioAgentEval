# Coding collection provenance and accepted analytical scope

The `.txt` snapshots preserve the experiment's original source bytes for inspection. They are historical collection definitions, not executable reproduction entrypoints. In particular, the original protocol and monitor contain superseded assumptions/claims. **Only the scope below and the accompanying paper define the retained analysis.** Do not execute or import these snapshots to reproduce results.

The accepted pipeline is `experiments/build_open_coding_results.py`, called by `python reproduce.py --coding`. Its inputs are `results/open_coding/episode_metrics.jsonl`, `assignment.json`, `collection_config.json` and `provenance.json`. All 1,182 original rows remain in original order, preserving every enrolled task and failure. The field projection omits candidate programs, self-tests, verifier stderr, endpoints, retry details and identifying local paths/hashes. Original evidence hashes and derived-data hashes have different roles and are recorded separately. The builder can recreate the projection from an explicitly supplied frozen source directory with `--project-source-dir`; it rejects any different raw episode hash. Aggregate reproduction never downloads weights, makes model calls or executes benchmark code.

The comparison prioritizes success, then workflow latency, then completion tokens, with a 10% larger-value relative tolerance for resource tiers. Resource tiers require joint success. A is single shot; B writes self-tests and may repair twice. First-pass comparisons use 295 preassigned cross-task pairs. Same-task comparisons describe all 591 tasks. The one planned unpaired arrival is excluded only from first-pass pairing, regardless of its outcome.

The sole retained uncertainty calculation is a **post-hoc application** of the fixed normal-mixture construction (`alpha=.05`, `rho=100`, `V_n=n`, no running intersection) separately to net preference and success differences. Its targets are running averages of history-conditional means for the first-pass collection process. It is not selection-adjusted, does not cover the complete fixed-roster functional, and the two marginal bands are not a joint 95% region. The success guardrail was never certified. Pair 60 is a retrospectively calculated negative-upper-endpoint crossing; all episodes were actually completed. No realized stopping savings are claimed. Same-task E2 results have no uncertainty interval. Contributed E2/R2 inference and betting-capital endpoints are excluded, not declared repaired.

The configuration used mutable benchmark URLs during collection; the bytes were subsequently matched to the immutable revisions in `provenance.json`. This is retrospective provenance repair, not an originally pinned download. All sanitized MBPP tasks are included, rather than only its designated test split. A separate six-task timing pilot was outside the 591-task roster and does not enter these analyses. The model's original file inventory includes tokenizer files; `mlx` runtime version was recorded as unknown, while `mlx_lm` was 0.31.3. Seeded requests do not promise bit-identical GPU sampling.

`source_manifest.json` hashes the preserved collection definitions. The analysis operates on archived verifier labels; it does not independently regenerate model outputs or rerun hidden tests. No full model-generation replication, production validation, author scientific attestation or unrestricted harness-license grant is implied.
