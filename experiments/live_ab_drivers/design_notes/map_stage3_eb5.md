## 2. The two load/coverage instruments that exist, and why only one can certify

Root's binding design choice (`reviews/live_load_root_decision_20260922_0237.md`, origin/main, 2026-09-22 02:49): the load criterion is "two distinct server-acknowledged decoding requests/occupied decoding slots throughout the verifier interval, recorded by pinned server-side lifecycle start/end events on the same host monotonic clock." Client POST-to-response timing does **not** establish this.

- `lab_load.py` (module docstring, `lab_load.py:1-97`; class `StreamingHttpLoad`, `lab_load.py:624-993`): the **client-stream diagnostic**. Declares `EVIDENCE_KIND = 'client_stream_arrivals'` (`lab_load.py:120`) and is refused as certifying evidence by `lab_prepare._coverage_verdict` (`lab_prepare.py:583-600`, checked against `EVIDENCE_SERVER_LIFECYCLE` at `lab_prepare.py:586-600`). Retained only as a diagnostic (root: "Stream events/timer lateness can remain diagnostics").
- `lab_lifecycle.py` (module docstring, `lab_lifecycle.py:1-50`; `observe()`, `lab_lifecycle.py:808-940`): the **certifying** reader. It parses `live_ab/slot_lifecycle-v1` JSONL records (`lab_lifecycle.py:71`) that only a patched llama.cpp server (`experiments/live_ab_serving/live_ab_slot_lifecycle.patch`, `lab_lifecycle.py:80`, `PATCHED_BASE_REV` = `4fea119de30f6a923992780f6fd5ccb0bee5d47d`) can produce, and returns `EVIDENCE_SERVER_LIFECYCLE` (`lab_prepare.py:472-473`).

`lab_lifecycle.observe()` itself is a **pure file/metadata reader** — it takes a log path, an `expected` manifest dict and a `process_outcome` and does no network I/O (`lab_lifecycle.py:808-826`). It explicitly labels two things as not yet real even in the reader: `"binary_sha256 and patch_sha256 are ECHOED METADATA, not verified against the running binary"` and `"record sequence numbers and the closing seal are not yet emitted or validated"` (`lab_lifecycle.py:882-887`).

## 3. EB5 worker/load resolution machinery (production path, but exercisable against a loopback mock)

- `lab_load.py:759-772` `_permit()` — the send gate: durable `load_intent` written under `_gate` before every POST; refuses once the terminal flag is set.
- `lab_load.py:774-880` `_one_generation()` — writes exactly one `load_terminal` (`done`/`error`/`abandoned_by_stop`) per intent, with `usage` parsed by `parse_usage()` (`lab_load.py:163-183`; malformed/absent usage is `null` with a reason, never zero).
- `lab_load.py:912-941` `stop()` and `lab_load.py:943-993` `resolution()` — `resolved` requires stop() called, thread not alive, every intent terminated, no stop-time unresolved record ever forgotten, and the durable ledger (re-read from disk, `read_load_ledger`, `lab_load.py:185-232`) agreeing with the in-memory record.
- `lab_prepare.run_reference_sweep` (`lab_prepare.py:77-125` docstring, gating code `lab_prepare.py:126-155`, acceptance code `lab_prepare.py:243-280` roughly): refuses before the first attempt unless `load_sources` are handed over and any source-bound observer is among them (`lab_prepare.py:145-155`); at acceptance, refuses (`PreparationRefused`) unless every source is `resolved` AND made ≥1 tracked load POST (rejects a `scripted_fixture` or a source with `intents < 1`) — this is the exact defect the 2026-09-23 review found ("a `ScriptedLoad([])` handed over while a real source still had a live thread ... that sweep was accepted").
- `lab_orchestrator.py:706-820` `phase_resolution_verdict(events, spool_stats, server_obs)` — **pure function**, no I/O: PASS only if (1) no `worker_unresolved` (every `episode_started` has an effective `worker_resolved` state in `exited`/`killed_reaped`), (2) no `call_unresolved` (every `llm_request` under a resolved worker has a terminal `llm_response`/`llm_error`, else listed `unfinished_calls` with `usage: null`), (3) no `spool_grew`/`spool_changed`/`spool_unreadable`, (4) no `server_busy`/`server_unobserved` (from `server_obs` mapping `{'held','observed','requests_processing','slots_busy'}`). Called at `lab_orchestrator.py:4824` inside trial close, and on FAIL forces `trial_aborted(unresolved_worker)` instead of `trial_ended` (`lab_orchestrator.py:4826-4833`).
- `experiments/live_ab/design/ARCHITECTURE_FINAL.md:1764` (event T33 `worker_resolved` schema), `ARCHITECTURE_FINAL.md:1777-1783` (`phase_resolution_verdict` mirrored by `lab_verify_log` as FAIL-level check `workers.resolved`), `ARCHITECTURE_FINAL.md:2213-2215` (rows 21a/21b/21c: restart-cap abort still drains and resolves every worker before any terminal record).

## 5. What `lab_mock_server` can and cannot stand in for

`lab_mock_server.py:1-18` (module docstring): "Scripted stand-in for llama-server, so the whole program is dry-runnable with no model... this is a **test double**: it never runs during a trial, and nothing it produces may be reported as an observation." Standard library only, loopback only (isolation matrix rule).

Endpoints implemented (`lab_mock_server.py:189` `do_GET` dispatches `/health`:192, `/props`:198, `/metrics`:211; `do_POST`:234 handles `/v1/chat/completions`/`/chat/completions`, non-streaming completion via `_complete`:251 which sets `requests_processing = active_slots` around the call):
- `/health`, `/props`, `/metrics` (`requests_processing`, `active_slots`, counters) — present.
- `/v1/chat/completions` — present, **non-streaming only**. `experiments/live_ab_controls/tests_lab_load_resolution.py:1-16` states this explicitly: "`lab_mock_server` has no streaming endpoint, so the controls that need a real socket and real `requests` run a TEST-ONLY SSE stub on loopback (`_SseStub`)... DEVIATION, recorded for root: the repair contract's hard rule allows network only as loopback to `lab_mock_server`; this stub is a second loopback server."
- **No `/slots` endpoint** — not found by grep in `lab_mock_server.py`. `lab_server.health()`'s `slots_busy` computation would degrate to `slots_read: False` / `slots_busy: 0` against the mock (`lab_server.py:329,337-341`), so `phase_resolution_verdict`'s `server_busy` branch (busy-slot case) cannot be exercised end-to-end through the real `lab_server.health()` call against the mock as it stands — it can only be exercised by calling `phase_resolution_verdict` directly with a synthetic `server_obs` dict (already model-free, see §6).
- **No `live_ab/slot_lifecycle-v1` emission** — the mock does not write the patched-llama.cpp lifecycle log format `lab_lifecycle.py` reads. The mock therefore cannot stand in for the certifying evidence producer; it can only stand in for the non-streaming request/response and `/metrics` counter surface.

## 7. Needs the real server / real capacity (cannot be prepared model-free)

1. **Actually building the patched llama.cpp binary** (`experiments/live_ab_serving/live_ab_slot_lifecycle.patch` against `4fea119de30f6a923992780f6fd5ccb0bee5d47d`) and running it against the real pinned GGUF weights to produce genuine `live_ab/slot_lifecycle-v1` records — this is the only thing that can certify EVIDENCE_SERVER_LIFECYCLE for real (root's binding decision, §2). No fixture or mock substitutes for this because the patch's correctness (does it actually emit the 4 timestamps at the right transitions, on the right clock) can only be checked by running it.
2. **Verifying two decoding slots are genuinely occupied concurrently** — root's "two distinct server-acknowledged decoding requests/occupied decoding slots throughout the verifier interval" requires actual GPU-backed concurrent decoding on the real server; a mock's `active_slots` counter is scripted, not observed contention.
3. **`/slots`-based `slots_busy` observation through the real, unmodified `lab_server.health()` production path** against a genuinely busy server — the mock lacks `/slots` entirely (§5), so exercising `server_busy` through the *actual* HTTP call chain (not a synthetic `server_obs` dict) needs either a real server or an extension to `lab_mock_server` (itself a decision root has not authorized, since `lab_mock_server` is described as a fixed "test double," ARCHITECTURE_FINAL.md §8 spec).
4. **`binary_sha256`/`patch_sha256` verification against the running binary**, and **record sequence numbers / closing seal validation** — `lab_lifecycle.py:882-887` names both as not yet implemented even in the reader; implementing the sequence/seal check is model-free (pure logic once the record shape is fixed), but *validating it against a live process* needs the real server.
5. **Named server/capacity evidence and a real host window** (`reviews/eb1_eb5_final_subset_bounded_review_20260925_2220.md` item 3; `reviews/prerun_bundle_go_nogo_20260923_2040.md` item 4 OD18/OD19) — root's disk/process observations are self-reported by the owner (73,185,824,768 bytes free at 22:00:52 UTC, 2026-09-25) and are not a root host inspection or capacity reservation; nothing in the repo can substitute for this.

TWO generation requests... Not a trial episode... calibration"). Re-running it or extending it into the actual stage-3/§5.8-item-3 240-episode calibration grid needs the real server and is a loaded episode, which is not authorized.

## 8. Bottom line for AREA

- The **contract** (`workers.resolved` / `phase_resolution_verdict` / EB5 ledger discipline) is fully specified and its pure-function/bookkeeping pieces are unit-testable today with fixtures and `lab_mock_server`, with no model.
- The **stage-3 two-stream loaded sweep driver itself does not exist as code** (confirmed at `lab_prepare.py:119` and `lab_load.py:91`); what can be built now is a model-free-tested *scaffold* for it (dispatch, permit/ledger, acceptance gate wired to `phase_resolution_verdict`-shaped checks) against `lab_mock_server`, per §6.5-6.6.
- What that scaffold cannot do — and what keeps EB5 open per root's own words — is demonstrate genuine concurrent decoding-slot occupancy on the real, patched production server. That is §7's territory: a real build, a real host window, and root's own capacity/freeze sign-off, none of which this read-only task is authorized to start.
