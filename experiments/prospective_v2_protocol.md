# Prospective pilot amendment: fixed-model workflow comparison

The original v1 protocol, 24 enrolled rows, zero completed trajectories, and retained US$0.0078588 reservation remain unchanged. The first OpenAI request returned HTTP429; a separately authorized minimal diagnostic identified `insufficient_quota` / `credit_balance_exhausted`. The amendment addresses provider availability before any completed pilot output was collected. It is not motivated by observed success or comparative performance.

The amended machine-readable `prospective_v2_protocol.json` was frozen before v2 requests. It retains the same 12 task IDs, task definitions, 40-step cap, four-error cap, 384 agent/192 user output limits, deterministic verifier, cost tolerance and joint-failure tie rule. The existing randomized order maps the original Luna arm to **standard** and the original Haiku arm to **verification**. Independent workflow-specific harness seeds were frozen; provider output reproducibility is not implied.

Both workflows and the user simulator now use the same model, `claude-haiku-4-5-20251001`, at temperature zero. Standard uses the untouched upstream default system prompt and telecom policy. Verification adds exactly:

> Workflow verification instruction: Before any tool action that changes account or device state, check the applicable policy and confirm that the requested change follows from the observed state. After a corrective action, verify the relevant state with an available diagnostic tool or ask the user to confirm the specific symptom. Keep customer-facing messages concise. Do not declare resolution without an observable check. This instruction does not override the domain policy.

This is a workflow comparison with a fixed model, not a comparison between language models. The instruction is applied only to agent requests in the verification arm; the common user simulator and scorer remain unchanged. The primary realized paired preference is verification versus standard, on success, then agent inference cost (5% of larger cost), then assistant tool calls, with two failures tied. The small prespecified pilot is descriptive and does not establish production A/B validity or superiority.

The same combined **US$4.00** ceiling includes the complete v1 retained reservation. `prospective_v2_spend_ledger.json` records the original immutable ledger hash and carries its accounted cost before admitting a v2 request. Every v2 request uses the original reviewed single-request reservation adapter; an additional v2 whitelist permits Haiku only. No retries, fallback or redirection are allowed. Unexpected provider behavior or infrastructure failure halts the remaining enrolled runs. Both completed and unrun enrollment rows are retained. No outcomes are replaced or tasks reselected if the budget prevents completing all pairs.

Public v2 trace summaries contain hashed content, tool names, token use and verifier outputs.
