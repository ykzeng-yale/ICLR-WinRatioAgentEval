## 5. New decisions that v2 introduces (not asked for by any single finding, needed to make the resolutions coherent)

1. Configuration B uses equal halves of the trial level (no pilot-informed allocation) and source strata only, so that the silence fallback needs no root confirmation of anything pilot-derived.
2. Roster rule without a size threshold (the 400-task cliff served only the margin switch, which is gone).
3. Block II of the root consultation (veto items common to A and B), so that a root objection to a common element cannot silently produce an unplanned configuration.
4. The integrity label rule (D35) and the closed `infra_flag` list.
5. Deferral of T3 as the single consequence of every T3-specific failure or objection.

## 6. What the reviser could not do or verify

- R4's simulator was not re-run (C12 is a pre-freeze step; P6 is interim and uses P5's latent model, including its unvalidated parameter w and an assumed A/A tie share of 0.08 among jointly solved pairs).
- No network: the Granite repository, its file list and licence file, the vendor pass rates for criterion (vi), the visibility of the GitHub repository, the behaviour of commit comments and of a public timestamp authority are unverified.
- No server was started: the content of `__verbose.generation_settings`, the echo (or not) of `cache_prompt`, `/metrics` semantics on cancellation, `/props.build_info`, GPU sharing between two server processes and the behaviour of `--jinja` with Granite are taken from R3 and the provenance auditor's source reading and are all covered by pre-freeze tests with fixed consequences.
- The execution-lock wrapper assumes that `agent.py` and `verify.py` reach `sandbox.run_program` through a name that can be wrapped before import; a unit test is prescribed, the code was not written.
