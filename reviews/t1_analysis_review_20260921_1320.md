## Accepted statistical choices

Per-cell/per-construction denominators are kept separate. Trial-level Monte Carlo Bernoulli summaries can use the declared independently generated trial paths: `vgen.stream` keys include namespace/cell/program/trial, and the outcome law has no shared program latent. Program-level union events have the number of complete programs as their denominator. No cluster correction is required solely because four independently simulated trials share a reporting label. The three constructions use the same path, so contrasts are paired, while the separately keyed delay cells are unpaired. The Wilson calculation is the ordinary marginal binomial score formula; it does not become simultaneous or anytime-valid merely because the underlying monitored bands are confidence sequences. The prior-development exposure label is appropriate.

## Required analysis corrections, in priority order

1. **The retain count is always read under the wrong label.** At line 167, `t.get("RETAIN", 0)` cannot count the writer's `RETAIN_INCUMBENT` label (`vrun.py:130–132, 1229`). Therefore any observed retention events disappear from `trial_retain`. Use the exact label and include `CONFLICT` explicitly so the decision-category counts reconcile to the trial denominator. This is a concrete code error, independent of whether a current cell happens to contain any retentions.

2. **The reported program event is not the frozen family error event.** Lines 116/132–133/158–172 report `any DEPLOY` over a program's four trials. Frozen section 9.2 requires `family_any_erroneous = any(false_deploy OR false_harm)`, where `false_deploy = DEPLOY AND NOT(mu_h>0 AND mu_s>-delta)` and `false_harm = RETAIN_INCUMBENT AND mu_h>=0`. All four laws have nonnegative hierarchy truth, so retentions are false harms even in favourable cells. C5/C6 deployments violate the success guardrail and are false deployments, although `deploy_is_error` at line 89 is currently false for those cells. Keep the existing any-deploy statistic as a clearly named descriptive quantity, but compute the frozen trial and family error events separately; define the generic deployment-error flag by the full conjunction or rename it explicitly as hierarchy-only. Program-any-deploy is useful descriptive detection probability, but it is not trial-level power and cannot substitute for family-any-error calibration. None of this requires new data.

3. **The code does not implement the prespecified calibration readout yet.** Lines 173–178 only emit miscoverage counts; Wilson intervals are generated only for program-any-deploy. Frozen sections 9.1–9.4 require trial-denominator two-sided and directional ever-miscoverage, trial false-deploy/false-harm/any-error, program family-any-error, their marginal Wilson intervals, and the frozen lower-limit-versus-nominal alerts. The existing CSV already contains the directional, eligible-look, conjunction and conflict information needed. Restore those summaries for all cells and all constructions, including the hierarchy-miscoverage positive-control readout for NAIVE in C2/C4/C6. The `>0.01` star in the CLI (line 264) is neither the frozen alert rule nor a labelled descriptive threshold and should not replace it. Use the V2 wording: a flag prompts diagnosis; neither a flag nor its absence establishes a theorem, and no favourable result is required.

4. **“No partially-powered operating point” does not follow from the grid's effect spacing.** Lines 21–24 and 236–237 infer this from the absence of intermediate `mu_h` values. Detection probability also depends on joint outcome law, variance, delay, guardrail effect, horizon and conservative boundary width. A nonzero fixed effect can have intermediate power at the chosen horizon. Retain the narrower limitation: this finite grid does not identify a power curve or a minimum detectable effect at a prespecified target power; it can estimate cell-specific correct-deployment and abstention probabilities with Monte Carlo uncertainty. Do not infer zero/one power from the listed means before evaluating the completed records.

## Stopping and reference interpretation

The script presently reports first-decision labels and all-path miscoverage without conflating them, but it omits the frozen timing/resolution summaries. Add the available `tau_prefix`, `tau_tick`, drain/finalization flags, unresolved fractions, and cost-narrowing summaries with their stated denominators. Report capped summaries across all trials separately from decision-conditional summaries and always show the capped/deciding fraction. These are readouts of simulated first crossing on paths continued to the fixed finalization tick; they are not measured runtime savings or a fresh live-stopped causal estimate.

No reference-band file is loaded by this script. Consequently it provides no H/D reference comparison, boundary-width comparison, or reference-driven power conclusion. If those diagnostics are subsequently summarized, retain the complete-information label and common-prefix/target qualifications; do not turn a latent full-information reference into the operational pending-outcome monitor. This is a limitation of the present analysis, not a request for another reference run.
