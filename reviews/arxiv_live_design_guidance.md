## Issue-comment-ready guidance

The ownership and prospective direction are appropriate. Please revise and freeze the following design details before collecting trial episodes; the existing functions are statistical primitives, not a complete validated live-monitor wrapper.

1. **Use one randomized orientation per pre-enrolled pair.** The accepted theorem requires two fixed, nonoverlapping arrival positions selected without their outcomes, then one fresh `R_i ~ Bernoulli(0.5)` assigning AB or BA. Each task still receives only one arm. Independent fair coins for individual arrivals followed by retrospective matching are a different design and do not directly implement this theorem. Queue two tasks, freeze the pair and baseline stratum, and log its coin before executing either. Do not form pairs by completion order or by searching for favorable/opposite-arm outcomes. State the primary target as the enrollment-running symmetrized cross-arrival preference and component effects; ordinary same-task preference is not identified by this design.

2. **Reveal order updates enrollment-indexed records.** Let `n` be the number of fully enrolled/randomized pairs. Process real events as they arrive, but keep every pair in its immutable enrollment position and update its existing score enclosure. Never append an update as a new observation, drop slow pairs, divide by the number completed, or sort scores by reveal time. At `n=0`, display the full range and do not decide. Both systems/protocols must be fixed; explain no cross-pair interference and the latent enrollment-order model. Shared serving contention or adaptive schedulers do not disappear merely because assignment coins are fair: isolate resources where feasible and log the fixed scheduling/resource policy and all concurrent load.

3. **Use the normal-mixture primitive with guaranteed partial bounds.** At a look and a selected enrollment prefix `n`, for each score `j`, use:

   ```python
   r = normal_mixture_radius(n, alpha=alpha_gate, rho=100., variance_process=n)
   L_j = sum(lower_j[:n]) / n - r
   U_j = sum(upper_j[:n]) / n + r
   ```

   Balanced orientation keeps the hierarchy and binary component differences in `[-1,1]`, so `V_n=n`. The bounds may be intersected with `[-1,1]`. They are two-sided bands for the running conditional-mean target. A simple primary rule uses the **current full enrolled prefix** `n=N(t)` at every event. Do not maximize lower bounds over different prefixes and call that a bound on the current running target; a prefix-envelope variant must report its selected prefix and target. The coding report's two marginal 95% bands are not a prospectively specified joint guarded rule and should not be copied unchanged.

4. **Concrete conservative error allocation.** For exactly four prespecified trials and two monitored scores per trial (hierarchy, success), a program budget of `.05` gives `.0125` per trial and `alpha_gate=.00625` per score. If a safety/compliance gate is added, divide that trial's allocation among all its gates. Freeze trial count and allocation before collection. The same simultaneous two-sided bands can support prespecified lower-bound deployment and upper-bound harm decisions; no extra split is needed merely for those two tails. Any additional candidate, primary hierarchy or confirmatory decision route needs its own allocation. Use `rho=100.` as a fixed reproducible starting specification, with its power checked before the freeze. The stationary no-split conjunction result is not the default for the proposed running-mean target under drift.

5. **Define endpoints and gates without fitting them to desired results.** For a success-first coding hierarchy, `compare(A, B, [Tier('success'), Tier('cost', higher_better=False, relative_tolerance=.05)], eligible=...)` can calculate complete scores, with cost eligible **only when both episodes succeed**; joint failures tie. Freeze actual cost units, absolute/relative tolerances, strict threshold equality behavior, verifier, retries, timeouts and all-attempt accounting. `compare` requires complete finite outcomes; do not impute pending success or resources. Start unresolved hierarchy scores at `[-1,1]`, enumerate feasible completions to narrow them, and collapse only with a valid final-score certificate. For success use `[sA_low-sB_high, sA_high-sB_low]`. Absence of failure so far is not success; elapsed cost is a lower bound only if it cannot decrease. Audit containment against every ultimately revealed score and every recorded look. Treat infrastructure loss using the frozen outcome/missingness rule, never deletion.

6. **Freeze a finite policy and preserve abstention.** A clear rule is deploy A when `L_h > 0` and `L_success > -delta`, both at the same current prefix/look. Prespecify whether harm means `U_h < 0`, `U_success < -delta`, or either; use the same declared target and thresholds. A minimum of 100 enrolled pairs is a reproducible screening choice, not a guarantee of adequate power. Choose a hard horizon and resource budget through the announced CPU planning study and report sensitivity before the freeze; the final plan may instead use a more feasible minimum. Choose `delta` for a defensible scientific or operational tolerance, not the value that makes the pilot deploy. Small success margins with this conservative bounded band can require many thousands of pairs. If the compute-feasible horizon has low power, call the run a prospective feasibility study and retain no-decision outcomes. Do not extend the horizon, loosen margins or replace the model after unfavorable monitoring. Label the purported deployable/harmful directions as hypotheses, not known truths; the reverse contrast uses new disjoint tasks/assignments.

7. **A traffic switch creates a new observation phase.** At the crossing, stop randomizing new pairs, retain and finish/resolve every already enrolled pair under its original assignment and frozen horizon, and log the exact switch time plus all in-flight exposure. Subsequent all-one-arm traffic is an operational follow-up cohort, not additional pairs for the original A/B estimator: positivity and the paired randomization have ended. The decision certifies a past enrollment-running target, not the most recent or future effect without stronger stability assumptions. Actual switches, calls, elapsed time and arm exposures can be measured. A single switched trial does **not** identify causal resource/latency savings versus continued A/B or another stopping policy; those are unobserved counterfactuals. A completed-prefix comparator evaluated on this run's available records is a coupled descriptive monitor comparison unless a valid randomized comparison of monitoring policies is designed. State this boundary in the protocol now.

8. **A/A is an implementation/null check, not four-trial calibration.** Use the same model revision, prompts/workflow, decoding law, verifier, caps and serving policy on both labels, with no label-specific seed or worker advantage. Reserve its alpha allocation and retain every result. One noncrossing A/A run does not establish a 5% false-decision rate or demonstrate equivalence; calibrated operating characteristics need repeated prespecified CPU null simulations and Monte Carlo uncertainty. A crossing is reported and investigated without silently discarding the run.

9. **Deliver a reviewable freeze before execution.** Post the task/pair manifest hashes, all four exact contrasts, open model revisions/licenses, scheduler/isolation model, alpha table, margins, `rho`, minimum/horizon/caps, seeds and seed receipt, all interval/decision code, sample append-only event schema and CPU planning results. A hash chain plus pushed milestones establishes recorded chronology only from those anchors; it does not prove an arbitrary local timestamp. Include deterministic tests of enrollment/reveal reorder invariance, repeated-update idempotence, enclosure containment, equality ties, joint failures and switch-phase exclusion. Record an exhaustive rather than selected set of planning outputs. Keep execution in the claimed new directories and pinned read-only core dependency; root can review the freeze without overwriting owner work.

## Primitive and theorem boundary

The proposed primary implementation should use `Tier`, `compare` and `normal_mixture_radius` from the pinned core. `betting_log_e_ternary` is a separate fixed-stake construction for ternary scores; it must not be fed weighted/nonternary scores or substituted silently for the declared normal-mixture rule. Its partial-score extension requires a reviewed adapter and the stated threshold guarantee; it is not automatically a calendar-time e-process. The accepted randomized disjoint-pair design is not a general bandit-router analysis. If the owner insists on independent per-arrival assignments rather than AB/BA pair blocks, request a separately identified and bounded score design before freezing any execution.

This review does not select additional tie/Pareto/grader grids or model families; those need a separate priority/budget decision and should not become prerequisites for arXiv v1 by default.
